# نتيجة الثانوية العامة 2026

موقع استعلام عن نتيجة الثانوية العامة، مبني على Next.js 14 (App Router) + PostgreSQL،
ومصمم بالكامل حول هدف واحد: أعلى عائد ممكن من Google AdSense مع الحفاظ على تجربة مستخدم
سريعة ومتوافقة مع سياسات Google.

## البنية

```
app/            صفحات الموقع (Home, Search, Result, Coordination, Appeals, FAQ, News, ...)
components/     مكونات قابلة لإعادة الاستخدام (AdSlot, SearchForm, ResultCard, Header, Footer)
lib/            الاتصال بقاعدة البيانات، تطبيع النصوص العربية، تحميل أماكن الإعلانات
prisma/         مخطط قاعدة البيانات + هجرة يدوية لفهرس البحث بالاسم + seed script
scripts/        سكريبت الاستيراد السنوي من ملف Excel
```

## التشغيل محلياً

```bash
npm install
cp .env.example .env   # عدّل DATABASE_URL و NEXT_PUBLIC_ADSENSE_CLIENT_ID
npm run db:generate
npm run db:push
npx tsx prisma/seed.ts                 # بيانات المحافظات + أماكن الإعلانات
psql "$DATABASE_URL" -f prisma/migrations/manual_trgm_index.sql   # فهرس البحث بالاسم
npm run dev
```

## النشر على Vercel

1. اربط المستودع بمشروع جديد على Vercel.
2. أضف Environment Variables: `DATABASE_URL` (Neon / Vercel Postgres / Supabase تعمل جميعها)،
   `NEXT_PUBLIC_ADSENSE_CLIENT_ID`، `NEXT_PUBLIC_SITE_URL`.
3. بعد أول Deploy، شغّل `npm run db:push` و`prisma/seed.ts` وملف `manual_trgm_index.sql`
   مرة واحدة على قاعدة البيانات الفعلية (من جهازك أو من Vercel CLI).
4. سجّل النطاق في Google AdSense وانتظر الموافقة، ثم حدّث `ad_unit_id` في جدول `ad_slots`.

## سير العمل السنوي (استيراد النتيجة)

```
رفع ملف Excel → تحقق → تنظيف → تطبيع → بناء الفهارس → استبدال بيانات العام السابق
```

```bash
npx tsx scripts/import.ts /path/to/النظام_الجديد.xlsx

# لو الملف خاص بمحافظة واحدة فقط:
npx tsx scripts/import.ts /path/to/file.xlsx --governorate=cairo
```

السكريبت مبني على شكل ملف الوزارة الرسمي بالظبط (نفس أسماء الأعمدة العربية: رقم الجلوس،
اسم الطالب بالعربيه، كود الشعبة، اللغة العربية... إلخ). الملف الرسمي **لا يحتوي على عمود
محافظة**، لذلك الحقل اختياري في القاعدة، ويتحدد فقط لو استخدمت `--governorate`.

أكواد الشعبة والحالة اللي الوزارة بتستخدمها مُفسَّرة في أول `scripts/import.ts`
(SECTION_LABELS و STATUS_LABELS) — راجعها وعدّلها لو عندك تأكيد رسمي مختلف لترتيب الأكواد.
القيمة `-4` في أي عمود مادة معناها إن المادة دي مش ضمن شعبة الطالب، فبيتم تجاهلها تلقائياً.

العملية بالكامل (validate → clean → normalize → replace) تتم في دقائق معدودة، ولا تحتاج
لإيقاف الموقع أثناء الاستيراد، حتى مع ملفات فيها عشرات الآلاف من الصفوف (الاستيراد بيتم
على دفعات من 5000 صف).

## لماذا هذا التصميم (ملخص القرارات)

- **صفحة النتيجة هي صفحة الربح**: كل قسم فيها يقود بشكل طبيعي لصفحة تانية (التنسيق، الأخبار،
  التظلمات، الأسئلة الشائعة) لزيادة عدد الصفحات لكل زيارة بدون Clickbait.
- **AdSlot موحّد وقابل لإعادة الاستخدام**: تغيير مكان أو شكل أي إعلان يتم من جدول `ad_slots`
  في قاعدة البيانات، بدون لمس الكود أو عمل Deploy جديد. كل الإعلانات Lazy-load عبر
  IntersectionObserver ومساحتها محجوزة مسبقاً لمنع CLS.
- **بحث سريع بالعربي**: `name_normalized` محسوبة مرة واحدة وقت الاستيراد، مش وقت البحث،
  وفهرس GIN + pg_trgm يخلي البحث بالاسم سريع حتى مع تكرار الأسماء.
- **قاعدة بيانات لموسم واحد فقط**: لا يوجد تعقيد متعدد السنوات؛ الاستيراد السنوي يستبدل
  البيانات بالكامل بمعاملة واحدة (transaction) لضمان عدم ظهور بيانات ناقصة للزوار.
- **صفحة النتيجة Noindex**: تحمي خصوصية الطلاب ومحتوى الموقع من مشاكل Duplicate/Thin Content
  مع Google، بينما تبقى مربحة إعلانياً لأنها الصفحة الأكثر زيارة.
- **لا Over-engineering**: لا توجد طبقات Enterprise غير ضرورية (لا Microservices، لا Multi-tenant،
  لا نظام مستخدمين) لأنها لا تزيد الزيارات أو الأرباح لموقع موسمي.
